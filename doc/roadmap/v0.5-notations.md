# v0.5 — Dynamic grammar

[← Roadmap](./roadmap.md)

`.synt` files: user-defined notations.

## v0.5.0-beta.1 — Dynamic grammar

### Tasks

- [ ] `.synt` file kind.
- [ ] Notations (precedence, associativity) and syntax rules.
- [ ] Three-phase pipeline: notation shapes, parsing, name resolution.
- [ ] The `elaboration` (`kir` →* `kir`, after the resolution): every
      notation replaced by its definition, looped until none is left; `kir`
      parameterized by what is left (`kir<NotationUse>` →
      `kir<Infallible>`), inference and typing only accept `kir<Infallible>`;
      each node keeps its origin (written, or the notation it comes from);
      fresh names never shown ([design](../design/pipeline.md#representations)).
- [ ] Error messages built on the fly by a notation: during its
      elaboration a notation can raise its own errors, and rewrite the
      errors found on its expansion in its own words
      ([design](../design/notations.md)).
- [ ] No sugar defined in the compiler: every sugar is a notation of the
      stdlib (`if` on `match` included, if it is sugar by then).
- [ ] Ambiguity and conflict detection.
- [ ] Kind keyword after `use` (`use synt …`, `use code …`), now that two
      kinds are importable.
- [ ] Stdlib operators (`+`, `==`, `<`, …) defined in `.synt` on top of the
      primitives and the type classes.
- [ ] `let* p := e in body` notation for `bind`, on any monad: `IO`,
      `State σ`, … (see [syntax](../design/syntax.md#monadic-let)).

### Tooling

- [ ] Formatter and LSP support the extended grammar.

### Done when

Stdlib operators (`+`, `*`, …) are defined in `.synt`.
