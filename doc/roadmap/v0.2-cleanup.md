# v0.2 — Cleanup and preparation

[← Roadmap](./roadmap.md)

Clean the current language and prepare everything the next versions build on: values, native backend and tooling.

## v0.2.0-beta.1 — Compilation phases

Split the command-by-command loop into phases on the whole source, so that
v0.2.0-beta.3 can remove the final dot. No syntax change.

### Tasks

- [x] Lexer: lex the whole source up to `EndOfInput` (no more "until `.`"),
      keep lexing after an error and return all errors.
- [x] Parser: parse a whole `pir::File`; recover on a broken command and
      return one error per broken command.
- [x] Middle-end names ([design](../design/pipeline.md#representations)): one
      crate `ir` with the modules `pir` (parse IR, from `cst`), `sir` (surface
      IR, untyped AST, new), `tir` (typed IR) and `lir` (low IR, new); one
      crate `pass` with every pass, among them the new `lowering`
      (`pir` → `sir`) and `codegen` (`tir` → `lir`); same module layout and
      type names in `pir`, `sir` and `tir`.
- [x] Typing: type a whole `sir::File` against an env, return a `tir::File`
      and all errors; a broken definition and everything that uses it are skipped
      silently, only the original error is shown.
- [x] Run: execute the typed items in order, only if no earlier phase failed.
- [x] Errors of all phases sorted by position before printing.
- [x] No driver: each pass is built by its builder and has one `run`;
      `pass::stdlib::Stdlib` chains them for the file runner, the REPL and
      the LSP; the formatter only lexes and parses (replaces the
      `Interpreter` trait and its three implementations).
- [x] Stdlib loaded once, through the same passes.

### Tooling

- [x] `startlang run --debug lexer,parser,lowering,typer,codegen`; the REPL
      has no debug output for now (`Set` removed).
- [x] LSP: diagnostics from every phase; `TypeOf` / `Help` info from typing;
      `Eval` run only in a sandbox (every `.st` for now) and only without errors.

### Done when

- `cargo test --workspace` passes; the `trycmd` outputs that change (several
  errors reported instead of one) are reviewed in the diff.
- A file with a lexing error, a parsing error and a typing error reports only
  the lexing error (the first failing phase stops the chain) and runs
  nothing; a file with two typing errors reports both, in source order.
- The lexer is called once per file.

## v0.2.0-beta.2 — REPL as a terminal UI

Remove the line-by-line REPL (`rustyline`) and replace it by a terminal UI
built on `crossterm`, before the syntax changes: once the final dot is gone
(v0.2.0-beta.3), the REPL cannot rely on it to know when an input ends.
No syntax change.

### Tasks

- [ ] `startlang tui`: a full-screen terminal UI on `crossterm` (`ratatui` +
      `tui-textarea`): an input area edited over several lines, the outputs
      and errors of each input above it.
- [ ] Enter runs the whole input; Alt+Enter inserts a new line (the same in
      every terminal).
- [ ] Pasted text (bracketed paste) goes into the input with its line breaks,
      without running.
- [ ] History: recall a previous input whole (↑ on its first line, Ctrl+↑
      anywhere), edit it and run it again; kept between sessions
      (`.start-history.txt`).
- [ ] Ctrl+C clears the input (quits on an empty one), Ctrl+D quits on an
      empty input, Ctrl+L clears the outputs.
- [ ] The REPL (`startlang repl`) and `rustyline` removed; its test
      scenarios ported to tests of the TUI.

### Done when

- An input of several lines can be typed, run with Enter, recalled and run
  again.
- `cargo test --workspace` passes; the scenarios of the old REPL are tests
  of the TUI; the key handling is unit-tested.

## v0.2.0-beta.3 — Cleanup

Clean the current language before building on it.

### Tasks

- [ ] All keywords in lowercase with short names (`def`, `type`, `eval`, …), no long aliases.
- [ ] No final dot: a command ends where the next command keyword starts.
- [ ] Remove the operator shortcuts (`$`, typeof, help).
- [ ] Remove the `.st` format: `.scod` (code) and `.snbx` (sandbox) only; `FileKind` and `Source` in `location`.
- [ ] Commands (`eval`, `typeof`, `help`) only in `.snbx` and the REPL.
- [ ] Machine integers: `i8` … `i64`, `u8` … `u64`; `ℕ` is removed from the
      code (it comes back in propositions, v0.6.0-beta.1).
- [ ] Integer literals: type inferred from the annotation or the context,
      optional suffix (`42u8`); no context → error asking for an annotation.

      ```
      def a : u8 := 42      (* u8 *)
      def b := 42u8         (* u8 *)
      def c := 42           (* error: ambiguous type *)
      ```
- [ ] `main` keyword in a `.scod`: no argument, returns an integer used as
      the exit code of the process.

      ```
      main : i32 := 0
      ```
- [ ] Until projects exist (v0.3.0-beta.2), a standalone file can be a `.scod` (with
      its `main`) or a `.snbx`.
- [ ] `assets/stdlib.st` becomes `assets/stdlib.scod` (new syntax, machine
      integers, no `ℕ`), still embedded in the binary and loaded
      automatically; replaced by the `std` project in v0.3.0-beta.2.

### Tooling

- [ ] Formatter and LSP follow the new syntax.
- [ ] Documentation: `doc/reference/grammar.md` and the guide updated to the new
      syntax; [changelog v0.2.0-beta.3](../changelog/v0.2.0.md#v020-beta3--cleanup) completed.
- [ ] `startlang run file.scod` runs `main` and exits with its value;
      `startlang run file.snbx` runs a sandbox.
- [ ] Test fixtures `startlang/tests/cmd/**/*.st` become `.snbx` (they use
      commands).

### Done when

- `cargo test --workspace` passes.
- Every scenario of `startlang/tests/cmd` is ported to `.snbx` in the new
  syntax, and the expected outputs (`.trycmd`) are reviewed in the diff, not
  only regenerated with `TRYCMD=overwrite`.
- No scenario is deleted to make the tests pass: the scenarios of removed
  syntax (`$`, `?:`, `?`, `Definition`, final `.`, `.st`) are replaced by
  tests checking the new error, whose help names the replacement
  ("`Definition` was removed in v0.2: write `def`").
- A `.scod` with `main : i32 := 0` runs and exits with code 0.

## v0.2.0-beta.4 — Values, `let` and `if`

Complete the value types and add local variables, conditionals and `panic`.
The affine typing (consumption, `const`, `copy` / `free`) comes with the
first allocated values, in v0.4.0-beta.1.

### Tasks

- [ ] Missing value types (scalars, copyable):
      - `unit`, with the value `()`;
      - floats `f32`, `f64` (IEEE 754, literals `1.5`, suffix `1.5f32`);
      - pointer-sized integers `isize`, `usize`;
      - `never`, the empty type of an expression that does not terminate,
        compatible with every type (e.g. in a branch of an `if`); temporary,
        removed with polymorphism (v0.4.0-beta.5).
- [ ] `panic "message"`: stops the program with a message. Like every
      built-in added from now on, it has a proper type: it returns `never`
      (`string -> α` from v0.4.0-beta.5). Until strings exist (v0.4.0-beta.3), its message is
      a literal written in place.
- [ ] `let x := e in body`: first local variables.
- [ ] `if c then a else b` on `𝔹`.
- [ ] Typed primitives on the value types, applied like built-ins (user
      functions come in v0.4.0-beta.4): arithmetic (`add`, `sub`, `mul`, `div`,
      `rem`), comparisons (`eq`, `ne`, `lt`, `le`, `gt`, `ge`), boolean
      operators (`and`, `or`, `not`), conversions between integer and float
      types. The operators (`+`, `==`, …) come as notations in v0.5.

      ```
      def x : i32 := if lt 1 2 then add 1 2 else panic "unreachable"
      ```

### Tooling

- [ ] LSP: hover shows the type of `let` bindings; formatter for `let`, `if`.

### Done when

`let`, `if`, `panic` and the primitives work on every value type (integers,
floats, `𝔹`, `Char`, `unit`).

## v0.2.0-beta.5 — VM removal

Replace the `vm` interpreter by native code generation.

### Tasks

- [ ] Remove the `vm` crate.
- [x] Internal startlang IR (`ir::lir`, *low IR*) lowered from `tir` by `codegen`
      (done early: the `vm` runs `lir` until it is removed).
- [ ] Cranelift backend: JIT (REPL, `.snbx`, LSP) and AOT (`startlang build`).

### Tooling

- [ ] `startlang build` produces a native executable in `target/`.

### Done when

`main` runs through the JIT and as a native executable.

## v0.2.0-beta.6 — Tooling foundations

Fix the bases of the tooling before the language grows.

### Tasks

- [ ] Dedicated compiler crate with a clear API; CLI and LSP are clients of it.
- [ ] Cargo-style CLI on files: `check`, `build`, `run`, `test`, `format`,
      `doc`, `tui`, `lsp` (`new` and project-wide commands come with projects,
      v0.3.0-beta.2).
- [ ] Tests with `test` / `assert` in `.snbx` files, and doc tests.
- [ ] LSP: diagnostics, hover, go-to-definition.

### Done when

A `.scod` and its tests in a `.snbx` can be checked, built, run and tested
from the CLI, and edited with the LSP.
