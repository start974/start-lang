# v0.4 — ADT, functions and polymorphism

[← Roadmap](./roadmap.md)

The core of the language: data types, functions, polymorphism, type classes
and the first stdlib.

## v0.4.0-beta.1 — Unions

Sum types and pattern matching. With unions come the first allocated values,
so the affine typing arrives here.

### Tasks

- [ ] Unions (sum types): constructors with or without arguments.
- [ ] Recursive types with `type rec`.
- [ ] `match e with | p => … | …` expression (definitions by case analysis
      come with functions, v0.4.0-beta.4); checks: exhaustiveness, no overlap (a
      last `_` means "the other cases").
- [ ] Affine typing (unions with arguments are the first allocated values):
  - [ ] Copyability as a property of the type (scalars and unions without
        arguments are copyable; can later be extended to type variables and
        type classes); tracking of reads and consumptions of the bindings
        (`let`, and from v0.4.0-beta.4 function parameters).
  - [ ] Consumption: a value is consumed when it is passed to a function at
        a parameter of type `T`; until user functions exist, only
        constructors and primitives consume; every other use is a read; a
        local value is consumed at most once.
  - [ ] Pattern matching never consumes: the bound parts are `const`.
  - [ ] Global definitions are never consumed: read when passed to `const`,
        implicitly copied when passed to a consuming parameter.
  - [ ] Across `if` and `match`: each branch is checked separately; a value
        consumed in one branch only is freed in the others.
  - [ ] `copy` / `free` universal keywords; implicit free of unused values
        with a warning (`_` to silence it).
  - [ ] Code generation of unions, copies and frees.

```
type color := | red | green | blue                  (* copyable *)
type rec list_i32 := | nil | cons i32 list_i32     (* allocated *)
```

### Tooling

- [ ] LSP: missing cases and overlaps as diagnostics.
- [ ] LSP: consumption errors and warnings; hover shows whether a binding is
      consumed or `const`.

### Done when

A list and a tree of `i32` can be defined and matched, and consumption errors
on them are reported with clear messages.

## v0.4.0-beta.2 — Tuples

Product types without names.

### Tasks

- [ ] Tuple types `T1 * T2 * …` and values `(a, b, …)`.
- [ ] Tuple patterns, also nested in union patterns.
- [ ] Affine typing of tuples: a tuple is copyable when all its components
      are; a tuple pattern never consumes.
- [ ] Code generation of tuples.

```
def p : i32 * 𝔹 := (1, true)
let (x, b) := p in …
```

### Tooling

- [ ] LSP: hover on tuple components; formatter for tuples.

### Done when

Tuples can be built, destructured and matched with unions.

## v0.4.0-beta.3 — Records, `string` and arrays

Product types with named fields, and the built-in allocated collections.

### Tasks

- [ ] Record types `{ name : T, … }`, values, field access `r.name`.
- [ ] Record patterns (all or some fields, `..` for the others).
- [ ] Affine typing of records: copyable when all fields are; field access
      is a read.
- [ ] `string` type and arrays (allocated); `panic` takes a `string`.
- [ ] Code generation of records, strings and arrays.

```
type point := { x : i32, y : i32 }
def origin : point := { x := 0, y := 0 }
match p with | { x := 0, .. } => … | _ => …
```

### Tooling

- [ ] LSP: completion of field names; hover on fields.

### Done when

Records, strings and arrays can be built, read and matched.

## v0.4.0-beta.4 — Functions

Functions, recursion and closures.

### Tasks

- [ ] Arrow type, abstraction, application, definitions by case analysis.
- [ ] `const T` on function parameters (inferred when a parameter is only
      read; always written in a `pub` type); returning a value consumes it.
- [ ] Tail calls in the code generation.
- [ ] `main` receives the arguments as an array (its size gives the
      count): `main : array string -> u8`.

      ```
      main := args => 0
      ```
- [ ] I/O primitives on an internal affine world token
      (`print : string -> world -> world`, …), not visible to the user yet.
- [ ] Recursion with `def rec` (also across files).
- [ ] Closures and affinity (a closure capturing a binding consumes it, or reads it).

### Tooling

- [ ] LSP: hover on function types, signature help.

### Done when

Functions, recursion and closures work, through the JIT and the AOT.

## v0.4.0-beta.5 — Polymorphic types

Polymorphic definitions and types.

### Tasks

- [ ] Type parameters, polymorphic definitions, type application.
- [ ] Remove the `never` type: built-ins that do not terminate become
      polymorphic (`panic : string -> α`).
- [ ] Affinity of type variables: a value of type `α` is affine (it may be
      allocated); `copy` / `free` work on it.
- [ ] `IO α` type hiding the world token, with `pure` and `bind`.
- [ ] `State σ α` with `pure`, `bind`, `get`, `put`, `modify`, `gets`, `run`
      (stdlib code, no compiler support).

### Tooling

- [ ] LSP shows instantiated types.

### Done when

Generic lists and functions can be written and type-checked.

## v0.4.0-beta.6 — Type classes

Needed by a generic stdlib (equality, ordering, display of any type).

### Tasks

- [ ] Type classes and instances.
- [ ] Standard classes for equality, ordering and display; the primitives of
      the value types become instances.
- [ ] `copy` / `free` may rely on type classes.
- [ ] `Monad` class; `IO` and `State σ` are instances.

### Tooling

- [ ] LSP: instance resolution errors.

### Done when

A generic function can require an instance (e.g. equality) and be called on
several types.

## v0.4.0-beta.7 — First real stdlib

The first real standard library, now that the language has ADTs, functions, polymorphism and type classes.

### Tasks

- [ ] First real stdlib (generic lists, string and array functions, …) in the
      `std` project.
- [ ] I/O functions (console, files, arguments) in `IO`.
- [ ] `State`, `StateT` (state next to `IO`) and generic monad functions
      (`map`, `sequence`, `for_each`, …).
- [ ] `main : array string -> IO u8`.

### Tooling

- [ ] Doc tests on the stdlib.

### Done when

The first stdlib is written in startlang and tested.
